# 2026-10-28 回复延迟排查

运行版本：4.0.0，阿里云杭州 ECS，2 核 4 GiB。时间为北京时间，另行注明 UTC 的除外。

## 结论

主要瓶颈是串行模型请求与回复工作流。当前样本没有显示 CPU、内存或 OneBot 本机通信是主要瓶颈。同题对照中云端比 Mac 慢约 0.4–1.1 秒，不足以解释实际聊天的 25–38 秒等待；不能据此认定迁移到云端本身造成了全部延迟。

本次仅做诊断和隔离实验，没有修改线上模型策略、镜像、配置或会话数据，没有重启服务，也没有向真实 QQ 好友发送测试消息。以下真实聊天数字来自已有记录的时间戳；主动模型实验使用合成输入、临时数据库和模拟 QQ。

## 确认的开销

### 1. 普通私聊也有两次串行模型请求

`qqbot/tulpa/runner.py` 的常规路径是：

```text
合并消息 → 读取上下文 → 模型决定计划
→ plan_chat_reply → 模型组织回复 → send_chat_reply
```

第一轮模型通常只返回规划；读到 READY 后还要再请求模型生成发送参数。真实模型实验中，这两轮占了普通回复的大部分时间。看图、搜索、计算、表达选择或模型漏调工具会增加轮数；同一会话还会顺序处理后续输入。

Tulpa 的规划、权限、消息新鲜度和幂等校验仍需保留；这些校验本身不要求各占一次独立的模型请求。

### 2. 默认思考与工具协议交互

实际响应返回了 `reasoning_content`，普通问候也会生成内部推理。官方文档说明 Qwen3.8-Flash 支持通过 `enable_thinking=false` 关闭思考，参见 [Chat Completions 参数](https://www.alibabacloud.com/help/en/model-studio/qwen-api-via-openai-chat-completions) 和 [深度思考用法](https://help.aliyun.com/zh/model-studio/deep-thinking)。

但仅关闭思考没有稳定解决本项目的问题：隔离实验中，问候先返回普通文字而没有调用工具，随后又有一次发送被拒绝，需要补调用；最终约 9.83 秒。另一条约 13.51 秒，其中一次规划模型请求本身用了 9.27 秒。相比默认模式的约 9–10 秒，这组样本没有稳定提速。

因此未直接修改线上 `enable_thinking`；需要先减少协议往返、改善工具调用约束，再对聊天与复杂任务分别评估策略。

### 3. 固定合并等待和气泡间隔

- 当前合并静默时间 1.2 秒，最长收集 4 秒。直接降为 0 会影响连续消息合并，不能当成无代价的优化。
- Tulpa 默认气泡间隔为 `min(4, 1.2 + 上一气泡字数 × 0.035)` 秒。
- 最近两条多气泡回复的首段分别为 90、56 字，对应额外等待 4.00、3.16 秒。该等待影响后续气泡和整轮完成时间，不影响首条到达。

### 4. 上下文存在重复和元数据负担

`infer()` 同时传入当前新消息、Tulpa 最近上下文和 QQbot 历史；近期信息有重叠。空白会话的第一次实验已经包含约 13.6 KB 消息载荷和 8.4 KB 工具 schema。

线上最近 40 条缓存事件序列化约 25.2 KB，而消息正文合计只有 1094 字；缓存还包括来源、时间、片段和发送回执等元数据。实际 `get_chat_session` 只取最近 20 条，不能把这 40 条的总量直接当作一次 API 输入量。另有最近 20 轮归档约 3.7 KB；同样不能未经去重就把它们全部解释为必要上下文。

冗余会增加输入和协议复杂度，但本次没有独立测出它对线上 38 秒样本的贡献，不将其作为已量化的全部原因。

## 后续优化顺序

1. 为每轮记录匿名关联编号、排队、模型轮数与耗时、工具耗时、首条和完整发送耗时。只记统计，不记录提示词、聊天正文、密钥或推理文本；补齐当前无法精确归因的部分。
2. 普通文字回复采用一次模型决策：模型给出回复和意图，宿主依次执行真实 Tulpa 规划、必要表达选择和发送。保留授权、过期输入阻断、撤回、取消、幂等与 UNKNOWN 不重发规则；复杂工具任务继续多轮。
3. 压缩模型可见上下文，去除重复近期历史和无需模型处理的发送回执字段，保留消息编号、引用、撤回、图片索引以及必要的长期记忆。
4. 短回复默认单气泡；保留确有语义需要的分气泡功能，再评估缩短间隔及合并静默时间。
5. 在以上约束稳定后，对闲聊非思考、复杂问题保留思考的策略做成对测试，不把关闭思考或单次测速当作质量与速度均改善的证明。

验收应覆盖首条到达和整轮完成两种指标，以足够样本统计中位数和 P95，并继续检查真实 QQ 的消息合并、图片、搜索、更正、撤回、停止与重复发送边界。
