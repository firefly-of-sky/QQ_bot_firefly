# v0.5.0：测试聊天问题整合与更新

根据 `chating_data` 测试记录和用户补充整理。原始聊天和图片仅留本地，已从 Git 与 Docker 构建上下文排除。

| 问题 | 结论与本版处理 | 验收方式与边界 |
| --- | --- | --- |
| 1. 多次提问无回复 | 按用户确认，原因是 QQ 风控导致电脑 QQ 下线。增加心跳与每 30 秒账号状态查询，区分接入连接和 QQ 在线 | 检查 `QQ account online/offline` 日志；下线仍需手动处理登录，不能消除风控 |
| 2. 回答过长、缺少对话空间 | 提示词默认短答、少量要点，必要时问一个问题，复杂多题允许分批 | 普通知识问题应先简答；“详细解释”仍可展开。提示词不是严格字数保证 |
| 3. 图片先被自动整页转录，后续需求才到 | 单独图片等待 3 秒；有文字则合并，没有文字只询问用途一次；图片链接在内存保留 10 分钟 | 分别测试图后 1 秒、图后 5 秒发“只解第一题”；均不应先自动 OCR |
| 4. 引用消息被拒绝 | 支持当前私聊的引用文字和图片；本地短期缓存及 `get_msg` 回查，核对来源 | 引用原图追问可重新读图；无权限、失效、旧机器人消息无法校验接收者时要求重发 |
| 5. 实时问题缺少实际搜索证据 | 接入独立 Tavily 搜索；支持 `/search` 和关键词自动触发，附实际来源链接 | Key 由用户申请。未配置、鉴权失败、限流、超时、空结果均明确失败，不伪装已联网 |
| 6. 添加好友时立即回答验证消息 | 忽略好友申请事件和已知自动通知，仅对通过好友后的主动消息回复 | 通过好友后不应收到自动欢迎；对方发“你好”后正常回复 |
| 7. 旧问题答案迟到、话题错位 | 保留同会话串行，提示模型聚焦本次问题；新增 `/cancel` 取消正在生成及排队的问题，错误提示标明原问题 | 模型答非所问的具体根因仅凭记录无法确定；不保证完全消除，需要继续真实对话观察 |
| 8. 复杂数学任务超时，没有进展信息 | 超过 12 秒提示一次处理中，保留 90 秒模型超时，支持取消；提示词鼓励按需求分批；输出长度用尽时提示续答 | 不自动重试或切换服务商；超时和失败轮不入有效历史。不能保证所有复杂题在时限内完成 |
| 9. 图片后续追问缺少原图细节 | 支持引用原图片再次送入视觉模型；初次需求迟到时仍可使用临时图片 | 已分析图片不自动附到所有后续问题，避免跨话题干扰；检查细节请引用或重发 |
| 10. 缺少定位链路、测试数据可能入库 | 添加请求编号、处理耗时与错误类型；测试聊天目录加入忽略规则 | 不记录原文、图片链接或 API Key；NapCat 自身日志独立管理 |

## 自动验证

本地 Python 3.14 与 Docker Python 3.12 均通过 56 项测试。本地与 Docker 使用同一套模拟测试，不向真实 QQ 发消息，不调用付费模型或搜索接口。覆盖原有聊天、好友隔离、持久化、模型与传输异常，以及图片等待/超时保留/过期/多图、引用权限、取消排队、搜索来源和错误分支。

## 升级与真实验收

```bash
docker compose build bot
docker compose run --rm --no-deps -v "$PWD/tests:/app/tests:ro" -v "$PWD/scripts:/app/scripts:ro" bot python -m unittest discover -s tests -v
docker compose up -d --no-deps bot
```

保留现有数据库、模型配置和 NapCat 登录数据。已有配置无需新增字段；搜索需要另填 `.env` 中的 `TAVILY_API_KEY`。建议用一位好友依次验证：添加好友静默、普通短答、图片后立即/延迟补问、引用图片、`/search`、`/cancel`、`/reset`。真实端到端验收需要 QQ 保持在线以及有效搜索 Key。
