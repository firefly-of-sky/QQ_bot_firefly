# QQbot 2.0.0

## 本版能力

- 默认启用原生工具调用，模型可根据工具结果多轮调整行动。
- `web_search`：模型自主生成检索词，支持普通/深度检索；不套用旧版薪资关键词计划。
- `read_page`：经 Tavily Extract 提取公开网页正文，可读取用户链接或展开搜索结果。
- `calculate`：有长度、节点、指数和数值限制的算术解释器，不执行 Python 代码。
- `current_time`：查询 IANA 时区的日期、时间与星期，默认 Asia/Shanghai。
- Markdown 人格每个新请求加载；工具权限由程序决定。
- 保留好友私聊、用户隔离、图片、引用、撤回、取消、模型切换、持久历史与文本排版。

本版仍只处理已添加好友的私聊。群聊、文件附件、语音、长期记忆、外部 MCP 和自动执行本机命令不在 2.0.0 范围内。

## 升级

已有 `config.toml` 和数据库无需迁移。新增配置缺省时采用下列值；旧配置也会默认进入 Agent 模式。先验证模型，再重建常驻 bot：

```bash
docker compose build bot
docker compose run --rm --no-deps bot python -m qqbot --check-config
docker compose run --rm --no-deps bot python -m qqbot --check-agent primary
docker compose up -d --no-deps bot
```

`--check-agent` 使用现有模型 Key，执行 `17*29` 的工具闭环，最多 3 次模型请求；不连接 QQ、不调用搜索，也不打印密钥或推理内容。普通文本检查成功不代表工具调用可用。

对不支持原生工具调用的模型，在对应 `[models.别名]` 内设置 `supports_tools = false`，使用兼容聊天。Agent 请求被拒绝时会明确报错，避免隐式降级让用户误以为工具已执行。

数据库表结构与旧版一致，可用旧代码重新构建回退；若添加了新配置字段，旧版启动前需移除这些字段。修改人格前可另存副本。不要使用 `docker compose down -v` 删除会话数据。

## 配置

以下字段放在 TOML 顶部、任何 `[models.*]` 之前：

```toml
agent_max_rounds = 6
agent_max_tool_calls = 8
agent_timeout_seconds = 240
tool_timeout_seconds = 30
tool_result_bytes = 8000
auto_search = true
persona_file = ""
```

`agent_max_rounds` 是允许工具调用的模型轮数，之后最多再请求一次最终回答。工具调用上限包含错误参数和缓存命中。一次请求可能比旧版产生更多模型和搜索费用；这些限制是调用量限制，不是货币费用上限。

`auto_search=false` 会在普通对话隐藏联网工具；显式 `/search` 仍可使用。没有 Tavily Key 时仅开放计算和时间工具。`search_max_queries`、`search_max_results`、`search_timeout_seconds` 只控制旧兼容搜索流程；Agent 使用上述工具预算和时限。

自定义人格：编辑 `personas/friendly.md`，配置 `persona_file="/app/personas/friendly.md"`（Docker）或 `persona_file="personas/friendly.md"`（本机）。首次修改配置需重启 bot，此后编辑这个 Markdown 文件会在下个请求生效。当前请求保持原快照。人格文件需为非空 UTF-8，最大 16 KiB。

`system_prompt` 继续保留，可设置全局偏好；人格补充表达风格。固定的工具与证据规则由程序附加。兼容模式使用原有 `system_prompt`，不加载 Agent 人格。

## 本机开发和不连接 QQ 的验证

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m qqbot --env-file .env --check-config
.venv/bin/python -m qqbot --env-file .env --check-agent primary
.venv/bin/python -m qqbot --env-file .env --ask "用工具算一下 (125+75)*12"
```

`--ask` 使用同一个执行核心，输出最终文字，不连接 QQ、不写聊天数据库。每次调用没有上一轮历史；工具由模型选择。`--model 别名` 可指定测试模型。

`--env-file` 仅显式读取指定文件，支持简单 `KEY=value`、带引号的值、注释；不执行命令，不展开 `$变量`。现有进程环境优先。Docker 已通过 `env_file` 注入环境，不需再传这个参数。

如果 macOS 的独立 Python 报“HTTPS 证书校验失败”，需安装/配置可信 CA 证书，或使用上述 Docker 命令。已安装 `certifi` 时，可在启动 Python 前将 `SSL_CERT_FILE` 设置为 `python -m certifi` 输出的证书路径。不要关闭 HTTPS 证书校验。

## 验收场景

1. 普通聊天直接回复，不强迫调用工具；计算问题产生工具结果后再回答。
2. 先查一个主题，结果不符时模型能够调整查询，再读取正文；工具循环会在预算内结束。
3. 处理搜索时 `/cancel` 或撤回提问，后续工具和最终回复停止，问答不落库。
4. 两位好友同时提问，上下文与工具结果互不混用；只有最终答案发给对应好友。
5. 服务商不支持工具、工具参数错误、搜索限额、正文提取失败均有明确处理。

自动测试使用合成消息、脚本化模型和本机模拟 HTTP/WebSocket，验证执行协议与生命周期；它们不能证明真实模型每次都会正确选工具，也不能代替实际 QQ 客户端验收。

2026-10-13 验证记录：

- 本机 Python 3.14 与 Docker Python 3.12 均通过 103 项测试。
- 当前配置的真实模型完成计算闭环：2 次模型请求、1 次计算工具调用。
- Tavily 实际搜索返回 5 条结果，Extract 成功读取 Python 官方文档正文。
- Docker 中真实模型完成“搜索官方文档 → 读取网页 → 回答”：5 次模型请求、4 次工具调用。
- 发布镜像构建成功，现有配置检查通过。上述真实接口检查使用公开测试问题，不向 QQ 发送测试消息。
