# QQbot 2.0.1：显式搜索兼容性与真实接口验收

## 修复

当前配置的模型接受 `tool_choice=auto`，但 `/search` 原先指定 `web_search` 的强制工具参数会被接口以 HTTP 400 拒绝。普通自主搜索能成功，不能证明这个命令可用。

显式搜索现在使用 `auto`，在系统提示中要求先搜索，并在程序返回最终答案前验证本轮至少有一次成功的 `web_search`。没有有效搜索资料时仍明确报错，不将模型凭已有知识生成的文字当成已核实答案。

增加了会拒绝指定工具参数的模拟 HTTP 接口回归。仅修改提示词而没有实际搜索结果时，已有测试仍要求本轮失败。

## 可重复的真实接口验收

运行以下命令会产生模型与 Tavily API 费用，需要 QQ 已登录：

```bash
docker compose run --rm --no-deps \
  -v "$PWD/scripts:/app/scripts:ro" \
  bot python /app/scripts/verify_live.py
```

脚本使用合成 QQ 消息和内存数据库，从 `Bot.handle` 入口经过真实模型、真实搜索/网页服务和最终回复逻辑。发送接口在本地截获，不向联系人发消息，不读取生产聊天数据库。QQ 只调用 `get_status` 确认连接。

检查连续对话、追问记忆、不同用户隔离、实际计算、`/search` 后读取网页、取消真实生成任务、QQ 在线状态。逐项输出结果，失败退出码为 1；不以旧历史答案冒充本轮成功。

这个脚本验证实际模型与程序处理链路；输入仍是合成事件、输出仍是截获结果，因此不能代替手机 QQ 到 NapCat 再到 QQ 客户端的完整实聊验收。

## 2026-10-13 验证记录

- 本机 Python 3.14 和发布镜像 Python 3.12 均通过 104 项回归测试。
- 真实接口验收 7/7 通过：普通对话、追问、用户隔离、计算、显式搜索并读取网页、取消正在执行的真实模型请求、QQ 在线状态。
- 计算工具返回 `2400`；搜索与网页读取用 3 次模型请求、2 次工具调用完成。
- QQ 的只读状态返回 `online=true`、`good=true`。测试期间没有向联系人发送测试消息。
