# QQbot 2.1.0：连续消息与自然打断

本版改变会话接话方式，沿用 2.0 的模型、工具执行层及数据库。没有数据库迁移，没有加入长期记忆。

## 连续消息合并

同一好友连续发送的文字、图片和单个引用，默认在停顿 1.2 秒后作为一次提问。合并内容按接收顺序以换行分隔，只调用一次执行流程、计一次提问频率并保存一轮问答。每个原始消息 ID 都保留关联，重放事件不会重复加入。

示例：连续发送“帮我看看”“[图片]”“主要看第三题”，会让模型一次收到图片和完整要求。合并后只有图片时，沿用图片暂存及用途询问；3 秒询问计时从完成本次合并后开始。

从第一条开始最多等 4 秒。每批最多 12 条，并受到输入字符上限约束；达到边界后开始下一批。普通命令、文件等不参与合并，两个分别带引用的消息也会分批，避免引用对象混淆。`/search 问题` 可接收后续补充；另一条 `/search` 会开始独立批次。

模型已开始处理后，普通补充消息进入下一批并排队；需要更新正在处理的问题时，请使用下述明确更正表达。本版未实现任意语义下的“是否说完”推断。

## 自然停止与更正

| 输入示例 | 行为 |
| --- | --- |
| `不用查了`、`先停一下`、`别回答了，谢谢` | 取消该好友的当前、排队及尚在合并的问题，清除待处理图片，发一条停止确认；保留已完成的历史 |
| `不用查了，帮我算17加29` | 停止旧任务，把后半句作为新问题 |
| `我刚才说错了，是上海`、`更正一下，是后天`、`改成上海` | 存在未完成问题时，以最近一个未完成问题为基础保留原要求、图片、引用资料和更正，停止该好友旧任务后重新处理；只有修正后的最终问答进入历史 |
| 没有未完成问题时发送更正 | 作为普通追问，使用已有历史回答 |

仅识别消息开头的明确表达，采用本地规则，不额外请求模型分类。纯引用、图片附文、代码块、引号内的表达、`他说不用查了`、`不用查了是什么意思` 不触发自然停止。支持的表达见 `qqbot/turns.py`；不能保证识别所有说法，`/cancel` 始终可用。

取消通过任务取消与会话代次共同阻止旧答案继续发送和落库，即使模型接口忽略取消也不能发送旧最终答案。已经发出到 QQ 的分段、已经提交上游的请求无法撤销，外部计费不保证停止。重新处理更正会产生新的模型/工具请求。

合并等待期间撤回其中一条，移除该条及依赖它的引用片段，继续处理其余片段。处理已经开始后，撤回任一关联来源会取消整轮。修正中的任务仍关联原问题和各次更正，撤回相关来源时同样取消。有效的主人 `/model` 和 `/reset` 会先停止未完成任务，防止旧批次在切换或清空后补答。

## 配置与部署

旧配置无需修改，新字段采用默认值。以下字段放在 `config.toml` 顶部、任何 TOML 表之前：

```toml
message_merge_seconds = 1.2
message_merge_max_seconds = 4.0
```

`message_merge_seconds` 可为 0–5 秒，0 关闭合并；`message_merge_max_seconds` 不小于前者且最多 10 秒。关闭合并不影响自然停止和更正。`/status` 显示 QQbot 版本、合并等待和交互能力。CLI 可执行 `python -m qqbot --version` 查看版本。

```bash
docker compose build bot
docker compose run --rm --no-deps bot python -m qqbot --check-config
docker compose up -d --no-deps bot
```

只更新 bot，保留 NapCat 登录和现有数据卷。内存中的合并片段与未完成任务不会跨重启恢复，需要用户重发。
