# QQbot 3.0.0 · 迁移到真实 Tulpa MCP

2.x 只是参考 Tulpa 的分层方式，消息调度和 Agent 均由本项目独立实现。3.0 将默认 QQ 运行时替换为 Tulpa MCP：不是更换提示词，也不是在原 Bot 外套一层接口。

## 已实现

- 固定并内置 Tulpa `0090b27fad42428c72e5cbaa903a140ca6bd51d4`，含 Linux 终端与好友私聊支持，保留 MIT 和第三方许可。本地补丁是独立数据根目录与 TUN 虚拟 DNS 的 IPv6 兼容。
- 使用原框架的 MCPService、权限 grant、会话、人格快照、实时 inbox、批次、Planner/Replyer、发送幂等与持久回执、语言学习。
- 常驻外部模型 Agent 通过真实 Streamable HTTP MCP 发现和调用工具；无需 DeepSeek 专属接口，沿用可配置的 Chat Completions 模型。
- 每个好友使用独立凭据，仅授权对应私聊。模型无法指定另一聊天目的地；管理员撤销凭据后不会自动重新授权。
- OneBot 回环桥兼容现有 NapCat 正向 WebSocket。桥接断线使 Tulpa 检测缺口；HTTP 写入不确定时不会伪装成功。
- `tulpa.toml` 支持配置额外 HTTP MCP 服务，动态发现完整嵌套输入 schema，并为工具添加服务名前缀。
- 自然取消、更正、控制命令、撤回取消推理；旧批次的新鲜度不会被后续 GET 悄悄覆盖。`/reset` 轮换真实框架会话。
- Tulpa 原终端管理可查看会话、权限、人格、学习和工具审计。服务监听容器回环地址，管理和模型凭据分离。

## 迁移与兼容边界

旧 `chat.sqlite3` 保留，每个私聊的已有历史作为模型背景，模型选择继续按会话保存。Tulpa 数据另存于 `/data/tulpa`。旧版 Bot 不在生产入口运行；其实现保留给本地兼容 CLI、旧版回归测试和 Git 回退。

模型必须支持原生工具调用。人格采用 Tulpa 快照语义，修改 `persona_file` 后 `/reset` 生效。现在的扩展配置需要重启 bot；支持 Streamable HTTP MCP，未实现 stdio 和 OAuth 交互登录。

Tulpa 最多 8 个活跃会话。普通好友空闲会话会释放，容量满时回收空闲会话；同时忙碌达到上限时不新增执行。默认没有开放群聊、语音、文件发送、好友/群管理及账号级操作。原框架具备这些接口不代表此版本已接好相应模型驱动和验收。

表达学习按框架真实用语证据、租约、分阶段模型调用和预算执行，新消息优先。它是语言表达库，不是任意事实的长期记忆；没有声称实现个人知识库或全历史检索。

`/reset` 清空当前会话 inbox 及本私聊问答背景，但不删除独立语言库和发送审计。撤回会取消推理、删除对应旧背景记录，并从新模型上下文排除；Tulpa 原始审计仍按上游策略保留，不能把它描述成全盘物理擦除。
