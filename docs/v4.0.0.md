## 登录失效与验收边界

10:52 的 NapCat 日志记录 QQ 登录失效并强制下线；容器未重启，未发生 OOM。用户重新扫码后，QQ 与 Tulpa 恢复在线。监控在 OneBot 接口消失时，也通过私有 WebUI 识别 `waiting_qrcode` 并报告 `qq_scan_required`，不会循环重启登录容器。

服务器常驻和进程恢复不能保证 QQ 登录永不失效。QQ 风控或登录失效仍需本人扫码；这与容器健康不同。备份目前位于同一块云盘，没有配置异地存储或外部掉线通知渠道。

整台服务器重启已在用户明确授权后执行；开机服务恢复已实测通过。QQ 自动续登未通过完全无人值守验收：持久化路径 `/app/.config/QQ` 与进程 HOME 均已核对，保存账号存在，QQ 明确要求手机验证。已补 `configure-login` 运维命令，自动绑定当前成功登录的账号；不通过循环重启尝试绕过验证。本人重新确认登录后，13:22 的真实私聊正确回复重启前口令云杉704；最终状态 `live=true, ready=true`。
