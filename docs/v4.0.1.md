# 4.0.1 两项延迟优化实验

实测日期：2026-10-28，北京时间。结果整理与最终回归：2026-10-30。

这是默认关闭的实验版本，未替换云端 4.0.0 镜像。没有改变模型、思考模式、消息合并等待或 Tulpa 的规划与发送校验，也没有发送真实 QQ 测试消息。

## 结论

- 上下文精简使模型可见的消息载荷约减少 **18%**，这组样本的整轮耗时中位数从 **10.66 秒降到 9.95 秒**。但出现一次违反“只能周末出行”的回答；小样本也无法证明稳定提速或对话质量完全不变。
- 短回复合并在固定文字回放中，使整轮完成中位数从 **5.64 秒降到 1.78 秒**，省约 **3.85 秒**，两段文字完整保留。该收益来自取消气泡间等待，基本不影响首条回复时间。
- 真实模型的基线普通问题已经全部单条回复；单独开启合并或两项同时开启，没有在本轮真实模型样本中表现出稳定提速。不能把固定回放的收益套用到每一条聊天。
- 两个开关继续默认关闭。当前结果更支持保留按需合并短回复的能力；尚不支持把两项同时开启作为已验证的普遍提速方案。

## 方法与范围

在原阿里云服务器的实际 amd64 / Python 3.12 运行环境中，以临时源码目录和临时数据库运行真实 Tulpa MCP 与 `qwen3.8-flash`。使用模拟 QQ，未读取真实聊天作为测试输入；人格与线上当前会话的配置比对一致。

每组 5 个场景、重复 2 次，共 40 次真实模型回答。顺序为：原版、精简上下文、合并短回复、两项同时；第二轮反序执行。每个场景重建会话并填入同样的 12 轮合成历史，避免上一题随机回答改变下一题背景。

场景包括：旧口令及预算、饮食、时间约束；连续消息中的更正；引用消息并实际调用计算工具；两点短建议是否完整；明确要求分两条消息时是否遵从。图片索引、引用、撤回、授权隔离、停止、长回复和混合媒体边界另由自动回归覆盖。

保留 1.2 秒消息合并静默、4 秒最长收集、2048 输出 token 上限和模型默认思考策略。各场景从发出合成输入开始计时，分别记录模拟 QQ 收到首条回复及整个 `infer()` 完成的时间。

测试与线上进程共用 bot 容器的资源限制；只同时运行一个实验进程。模型服务负载、缓存、随机输出长度与工具调用轮数仍有波动。这不是盲评，也不是足够规模的统计性能或综合质量评测；未测真实 QQ 公网送达耗时，不报告有统计意义的 P95。

## 真实模型结果

所有样本均纳入耗时统计，包括质量检查未通过的那一次，没有筛掉慢样本或不利结果。

| 配置 | 样本数 | 预设约束检查 | 首条回复中位数 | 整轮完成中位数 | 整轮范围 | 消息载荷中位数 |
| --- | ---: | ---: | ---: | ---: | --- | ---: |
| 原版 | 10 | 10/10 | 10.22 秒 | 10.66 秒 | 9.62–17.76 秒 | 26,424.5 字节 |
| 仅精简上下文 | 10 | 9/10 | 9.57 秒 | 9.95 秒 | 6.28–12.79 秒 | 21,720 字节 |
| 仅合并短回复 | 10 | 10/10 | 10.67 秒 | 12.06 秒 | 8.09–17.51 秒 | 26,423.5 字节 |
| 两项同时 | 10 | 10/10 | 11.50 秒 | 11.94 秒 | 8.34–21.47 秒 | 21,720 字节 |

“消息载荷”是消息列表的 UTF-8 JSON 序列化大小，不包含工具 schema，不是精确 token 数、HTTP 线上字节数或费用。工具 schema 保持不变；不能据此声称总成本下降 18%。

### 质量问题与评分修正

合成历史明确要求“只能周末”。仅精简上下文的第一轮记忆题回答包含“周五晚出发或周六早出发”，违反时间约束，记为失败。旧口令、预算与饮食限制在该回答中仍然存在；对应归档也未被去重删除，但这不足以证明回答质量合格。

最初的关键词检查仅检查是否提到周末等信息，漏掉了矛盾。人工复核后收紧规则，用相同最终规则重评全部现有答案，并添加“提到约束但给出冲突建议”的评分回归测试；没有为了改善分数重新抽取答案。

上述通过率仅对应列出的预设检查，不代表开放式对话质量一致。例如合并短回复组的一条回答还把“不吃花生”扩展成了“过敏忌口”，属于未经提供的额外推断。合并发生在模型生成之后，不能把这种随机表述归因于文字拼接，也不能据此宣称模型没有其他质量问题。完整合成回答保留在结果文件中供复核。

## 固定文字回放：单独验证发送收益

补充 4 次真实 Tulpa 回放，采用原版、合并、合并、原版的顺序。模型由固定工具参数夹具代替，不请求模型 API；每次都提交完全相同的两段纯文字，总长度小于 300 字。这样可以隔离模型服务波动。

| 配置 | 次数 | 内容检查 | 首条回复中位数 | 整轮完成中位数 | 消息数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原版 | 2 | 2/2 | 1.715 秒 | 5.635 秒 | 每次 2 条 |
| 合并短回复 | 2 | 2/2 | 1.688 秒 | 1.782 秒 | 每次 1 条 |

合并以换行连接，文字逐字保留。单条原始回复没有这部分额外收益；明确要求分条的真实模型场景在全部配置下均仍收到两条消息。

## 实现与开关

4.0.1 代码中可在 `tulpa.toml` 分别设置：

```toml
[performance]
compact_context = false
single_bubble_short_replies = false
```

旧 4.0.0 镜像不识别这些设置，不能只修改线上配置来启用；需要包含本次代码的新镜像。本次未部署新镜像。

上下文精简仅在原消息编号和完整问答文字都匹配时，删除重复归档；缺少来源、回复不完整、撤回或匹配不确定时保留归档。保留当前输入、较早记忆、消息与引用编号、图片索引、语义提示和未知语义字段；删除运输来源、重复会话地址、接收时间、发送回执，以及由宿主管理的等待续接指令。原始数据库不删除这些字段。

短回复合并仅处理 2–3 个纯文字气泡，合计含换行不超过 300 字。超长、媒体、引用或 @ 参数、未知字段和无效队列原样交给框架；检测到明确分条要求时不合并。分条意图检测是保守的中英文规则，不能保证覆盖所有自然语言表达。没有缩短内容，也没有绕过 Tulpa 的计划、权限、新鲜度、撤回或幂等检查。

另外修正了集成测试中的异步竞态：模拟 QQ 收到消息不等于框架已返回发送回执、历史已写入；测试先等待历史可见再断言，不以固定睡眠代替完成条件。

## 复现与检查

在已有配置的源码环境中，每个变体必须启动独立进程。真实模型命令会产生 API 费用；QQ 始终为合成夹具：

```bash
python scripts/benchmark_tulpa_latency.py --allow-billable --variant baseline --output baseline.json
python scripts/benchmark_tulpa_latency.py --allow-billable --variant context --output context.json
python scripts/benchmark_tulpa_latency.py --allow-billable --variant bubble --output bubble.json
python scripts/benchmark_tulpa_latency.py --allow-billable --variant both --output both.json
python scripts/benchmark_tulpa_latency.py --replay-only --variant bubble --output replay.json
python -m unittest discover -s tests
```

最终完整回归共 154 项；专项覆盖未重复历史的保留、来源隔离、多段输入与完整回复匹配、引用和媒体索引、撤回内容脱敏、无截断拼接、显式分条、长回复与混合媒体保护。真实 Tulpa 集成还覆盖合并后实际保存的完整文字、停止、更正、去重、好友隔离和工作进程恢复。

原始计时与合成答案、统一重评分保存在 [实验数据](benchmarks/2026-10-28-latency.json)。不包含真实聊天、API 密钥或 QQ 凭据。
