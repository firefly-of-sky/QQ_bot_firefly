# 5.0：主人授权的 QQ 操作代理

5.0 在真实 Tulpa MCP 上增加独立账号操作代理。普通聊天继续走 `plan_chat_reply → send_chat_reply`；主人额外获得 `qq_tools`（按需查询工具与参数）和 `qq_execute`（执行动作）。当前私聊的戳戳、转发等互动仍经同一发送队列，避免绕过批次与回复计划。

## 授权与运行

本次用户选择“广泛自主”：已授权的普通 QQ 操作可自行决定，账号安全和付费操作需要确认。当前实现不向模型提供账号凭据、安全设置或付费 API；这些需求必须交由本人处理。删除主人联系人也交由本人在 QQ 客户端确认，以保护控制通道。

部署者在 `tulpa.toml` 显式登记：

```toml
[autonomy]
enabled = true
authorization_id = "broad-20261031-v5"
capabilities_file = "/data/tulpa/provider-actions.json"
background_friend_requests = true
writes_per_minute = 10
background_per_hour = 12
```

`authorization_id` 表示一次部署者授权登记。凭据单独保存于数据目录的 `operator-connection.json`（0600），不进入模型上下文。相同登记 ID 不会自动补回管理员撤销的权限，撤销凭据也不会被启动流程偷偷重建。普通好友没有账号操作代理；模型参数不能冒充主人。

真实 OneBot 好友申请进入持久化任务队列，由模型读取实际申请并决定接受或拒绝。宿主将此任务严格限制于触发事件对应的申请人，不能借申请备注执行其他账号操作。最多排队 32 项，每小时默认 12 项；暂停时不接收新自主任务。

## 操作状态与控制

- `/qq`：查看当前授权及接入程序支持的动作数量。
- `/autonomy`：查看是否暂停及各类动作可用数量。调用和后台任务状态另保存在操作账本中。
- `/autonomy pause`：持久化暂停，停止后台任务及新的自主操作，仍可文字聊天。在途操作可能已经完成，不能承诺撤销。
- `/autonomy resume`：恢复。不会恢复被管理员撤销的框架权限。
- `/status`、`/models`：显示实际完整模型 ID，避免别名掩盖模型切换。

`operator.sqlite3` 保存调用参数摘要、清理后的执行结果和任务状态；原始账号凭据不写入账本。写操作按输入批次生成幂等键，重启后的执行中状态转为 UNKNOWN。UNKNOWN 不自动重试，也禁止同一输入换参数重发。明确拒绝与网络结果未知分别处理；缺少空间 tid 回执的发布不会标成成功。每分钟写操作默认最多 10 次。

## 验证与部署

自动回归覆盖真实 Tulpa MCP、权限撤销、普通好友隔离、重启去重、暂停、好友申请任务及错误回执。`scripts/verify_qq_operator.py` 默认使用隔离的模型和 QQ；`--real-model --allow-billable` 使用实际模型但 QQ 仍为隔离夹具，可验证工具选择而不操作真实好友或动态。

云端更新复用已验证的 4.0 运行时依赖，构建 5.0 软件层；不重新登录或重建 NapCat。切换前备份配置和数据库，保留旧镜像、旧 release 与配置快照。QQ 登录失效仍需要本人手机确认，软件不能保证账号永不掉线。
