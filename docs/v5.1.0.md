# 5.1.0：跨对话的长期用户画像

每个 QQ 好友独立保留精简画像：长期表达习惯、偏好、背景、兴趣、持续目标，以及值得保留的经历线索。画像不是历史窗口合集，不保存完整会话或无限增长的逐字聊天记录。主键包括机器人账号和好友标识，改昵称不会另建画像，不同好友/机器人账号不共享。

普通回复成功后，后台模型结合既有画像和当前用户消息提出少量更新；只接受能在当前用户原话中找到证据的条目，既有画像和助手回答不能作为新证据。每次最多 4 项、每项 160 字，每个用户最多 32 项；相同属性更新覆盖。只保留摘要和来源消息编号，不额外长期存储证据原文。它从升级后的新聊天逐步形成，不默认扫描过去全部窗口。

明确自述标为 explicit，推测标为 tentative，推测不能覆盖已确认信息。推测超过 30 天不再读取。回复时按偏好及当前问题的相关性选择画像，总计不超过 6000 字节。短提示可借助画像调整详略、用词和解释背景；当前明确要求优先，不清楚的关键条件仍需询问，画像不能成为权限或事实凭证。自动提炼是模型判断，可能漏记或归纳不准；可以查看画像，直接更正，并彻底清除后重新形成。

`新对话`、`开启新对话`、`/new` 或 `/reset`：清理当前上下文并轮换真实 Tulpa 会话，保留画像。`/profile`：查看自己的画像，推测项会标明。`/forget`：清除自己的画像及当前上下文，开启新会话。清除会提升版本号，已排队或推理中的旧画像更新无法再写回；用户撤回对应源消息时，也会删除由该来源形成的画像条目。

**手机 QQ 本地清空聊天窗口通常不会发出服务器可见的新会话事件。** 它不会清除画像，但若想同时开启独立的新对话，请发送“新对话”；无需换账号或清除全部长期信息。

提炼在实际回复之后运行，不等待它完成再给普通回复；后台一次最多一个模型请求、25 秒超时，每个好友待处理队列最多 8 批。开启新对话会尽量等待最近的提炼（最多 5 秒），尚未完成的更新也可继续落入长期画像。提炼失败不影响已发送的回复，不把失败称为已记住。进程刚退出前尚未完成的提炼可能丢失，已经提交到 SQLite 的画像会保留。密码、验证码、密钥、身份号码、临时测试暗号等有模型规则与本地过滤，不作为用户画像保存；这不是对所有敏感语义的完美分类器。

画像保存在现有私有 SQLite 数据库中，已有云端备份会一起保存它；QQ 登录失效仍然需要真实登录，画像不修复接入会话掉线。保留现有近期对话的读取上限，`/new` 后不再把上一窗口全文拼接进新窗口。用户主动清除的是在线画像，既有轮转备份遵循原来的保留策略。

本机完整回归 184 项通过。新增测试覆盖数据库重开与上下文重置后的画像保留、好友隔离、更正覆盖、推测不覆盖事实、画像条数及注入容量上限、原话来源验证、测试暗号过滤、撤回删除及遗忘与后台写回竞态。真实 Tulpa MCP 集成（模拟 QQ/模型）通过自动提炼、新窗口轮换、上下文清理、跨窗口画像读取与遗忘；真实模型与云端验收另记录在 acceptance-v5.1.0.json。

云端已激活 `5.1.0-profiles`，Bot 5.1.0 实测 ready=true、QQ 在线，原 NapCat 容器未更换；升级前已做私有数据备份。画像表迁移完成，初始画像条数为 0，没有批量推断旧窗口。Mac QQ 实际 `/profile` 收到“目前还没有形成你的长期画像”，证明命令从实际 QQ 进入新版 Bot 并返回。

真实模型已通过独立模拟 QQ 的画像提炼、新窗口读取、好友隔离、遗忘验证。云端完整回归 184 项运行、183 通过、1 项缺少 Node 而跳过，单独的真实 Tulpa 会话画像测试也通过；验收脚本按框架可能替换会话对象的实际行为跟踪新会话。机器可读结果见 [5.1.0 验收](acceptance-v5.1.0.json)。
