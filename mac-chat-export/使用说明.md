# QQ 聊天整理 · Mac v0.3.1

可先双击 `build/QQ聊天整理.app` 让系统识别应用，再双击 `QQ聊天整理.shortcut`，在系统“快捷指令”中添加“QQ聊天整理”。运行它会打开配套 Mac 应用；也可直接使用应用。在应用内点击“启动 QQ 批量读取”。应用需保留在此文件夹内；也可直接双击 `QQ聊天整理.command`。

该快捷指令使用系统自带“打开 URL”操作，通过本机 `qqchatarchive://open` 地址打开配套应用，不需要开启快捷指令的脚本执行权限。此地址只显示应用窗口，不会自动启动 QQ 或读取记录。配套应用及读取组件仅适用于 Mac。

## 首次使用

1. 完全退出电脑上日常使用的 QQ（在 QQ 中按 Command+Q）。
2. 启动本工具，阅读说明，确认接受后输入 `YES`。
3. 使用**需要导出记录的个人 QQ 账号**扫码登录，不要登录项目中的机器人账号。
4. 打开读取组件显示的本机导出页面；如果页面未自动打开，使用组件提供的登录链接。若要求访问令牌，只在本机页面填写，不需要发到聊天中。
5. 选择好友或群聊、时间范围。**格式选 JSON，开启图片/资源下载**。JSON 模式选择普通单文件或分块 JSONL，不选上游的“流式 ZIP”；本工具会自行生成最终 ZIP。推荐先导出一段有已知原图和较早消息的小范围记录，再扩大范围。批量选择多个会话会分别生成归档。
6. 每个导出任务完成后，工具自动在 `output/` 生成文件夹和 ZIP。在应用中点击“打开整理结果”。

几十万条以上的大型会话建议选择 JSON 的分块 JSONL 模式，同样可以自动整理。首版自动整理不处理 HTML/TXT/Excel 导出任务；这些格式无法可靠恢复每条图片消息的对应关系。

```text
output/<本次导出>/
├── data/<会话名称与标识>/
│   ├── chat.txt
│   └── images/
│       ├── 001.jpg
│       └── 002.png
└── 整理报告.json
```

`chat.txt` 保留原导出中的发送者、时间、消息顺序，以及 `[图片: images/001.jpg]` 这样的标记。相同图片内容共用同一文件；不同内容即使原文件名相同也不会相互覆盖。真实格式按文件内容识别。取不回的图片明确标为缺失，整理报告记录缺失引用数。

ZIP 内保留相同结构，可直接传到手机或其他设备。“整理报告.json”是归档附加文件，不混入聊天正文。

## 当前能保证什么

已验证 QCE JSON/分块 JSONL 的转换、文字图片对应、资源缺失标记、转发消息展开、不覆盖历史归档、ZIP 目录结构，以及完成任务后自动整理的规则。

首次启动后已验证 QCE 服务健康、QQ 显示在线、鉴权任务接口可连接，尚未产生真实聊天导出任务。能导出多少历史取决于 Mac 本地聊天记录、QQ 的可访问漫游范围、会员/服务状态及图片是否仍可取回；不能把导出成功等同于“恢复所有历史”。本工具不会编造缺失的时间、姓名或图片。语音、视频和其他消息保留类型与原字段说明，首版不复制这些媒体文件。

## 读取组件及首次启动的影响

读取组件是非官方开源 [QQ Chat Exporter](https://github.com/shuakami/qq-chat-exporter) v6.3.2，使用其 Apple Silicon Mac 预览包。官方发布包 SHA-256：

```text
a241a2a694edb317fa494e9f9a0bda79284937be97afa7bfea269741b7f15a9a
```

按上游 [Mac 部署说明](https://shuakami.github.io/qq-chat-exporter/docs/macos-deploy.html)，首次启动会创建专用 QQ 副本并重新签名，该副本失去 App Sandbox 保护。副本与日常 QQ 共用聊天数据库，运行期间应保持日常 QQ 退出；原始 `/Applications/QQ.app` 不被修改。首次运行必须由你明确选择是否接受。

本工具使用独立端口 40683/40684 和独立的 QCE 访问凭证，不替换现有 QQbot 配置或机器人登录。QCE HTTP 服务上游默认监听所有网卡，但本工具创建的凭证配置仅允许本机 IP，保留鉴权，不配置公网访问。不要将此端口转发到公网。QQ 登录本身与 QQ 服务通信；整理、编号与打包在本机执行，不调用大模型。

上游可能把原始导出放在“文稿”中的 QCE 默认目录；本工具自动根据完成任务的文件路径读取，最终目标结构统一保存在本文件夹 `output/` 下。请保留原导出及其 `resources/`，直到整理成功。原始导出不被删除。

停止时，在应用中点击“停止读取”，或在读取终端按 Control+C。停止会中断未完成的导出任务，已生成的归档和原始导出保留。正常关闭读取终端时，工具也会停止后台读取和整理组件；只关闭此应用的主窗口不会停止终端中的读取过程。

重复点击启动不会创建第二套组件。若旧版或异常退出留下了本项目的残留进程，下一次启动会核验任务状态：没有未完成任务时自动清理后启动；有未完成任务或状态无法核验时，保留组件并提示使用“停止读取”。其他程序占用同一端口时不会被自动停止。端口刚关闭后的系统等待状态不再被误报为服务占用。

若看到旧版的“端口 40683 已被占用”，请重新打开 v0.3.1 应用，点击“停止读取”，待提示完成后再启动。也可在本目录运行 `python3 launch.py --stop`。停止程序按本项目的完整程序路径、账号和进程启动时间核验，不通过进程名或端口批量终止其他服务。

## 从已有导出重新整理

如需重新整理已经导出的文件（例如补齐缺失图片之后），在本目录运行：

```bash
python3 archive.py "/完整路径/导出.json"
```

分块导出可选 `manifest.json` 或它所在的文件夹。每次生成新的归档，不覆盖旧文件。单个 JSON 会读入内存；分块 JSONL 按行处理。

## 开发与环境核查

本机已安装 Python 3.14、Swift 和官方 QQ 7.0.2；读取组件需要 Apple Silicon 和 Python 3.11 或更新版本。重新生成应用：`bash build_app.sh`；重新生成并签名快捷指令：`python3 make_shortcut.py`。检查已下载组件：`python3 launch.py --check`，该命令不启动 QQ、不生成登录凭证。运行组件及生成的应用不纳入 Git；重新克隆项目后，可先运行 `python3 prepare_runtime.py` 准备固定版本的读取组件，再生成应用。
